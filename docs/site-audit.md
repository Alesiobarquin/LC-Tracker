# LC Tracker site audit

LC Tracker plans LeetCode practice from a daily time budget, practice history, and an optional interview date. The review assumes a personal study workspace with self-reported outcomes, occasional concurrent devices, and long-lived practice histories. It covers the landing page, public references, navigation, sign-in and onboarding, Today, coding and recall sessions, the library, syntax, evidence, Settings, Study Chat, and the data paths behind them.

## Remaining findings

1. **Individual practice saves reread full histories.** A coding save fetches all problem-progress pages and the recent timing window before it constructs the transaction, even when the task is unrelated to a sprint retrospective. Accounts with many histories pay this cost on each save. A targeted confirmed read for the common path could preserve the current revision checks and leave the retrospective’s broader reads intact. [Save path](../src/services/userData.ts)
2. **Large bundles still affect first use.** Vite reports 230 kB gzip for App, 222 kB for the code editor, and 128 kB for the extended catalog. The latter two load on demand. To identify the biggest remaining startup cost, measure transfer and execution separately on a low-end phone and compare public landing, library, and signed-in Today. [Build configuration](../vite.config.ts)
3. **Admin feedback reads rely on single responses.** The admin list and header count can omit older rows once feedback exceeds the project’s PostgREST row cap. The application already has a pagination helper that continues through short pages. This matters when the inbox grows past the cap. [Admin inbox](../src/components/AdminDashboard.tsx) · [Count](../src/components/Layout.tsx) · [Pagination](../src/lib/pagination.ts)

## Verification scope

The Playwright interface suite exercises fourteen surfaces at desktop and phone widths in both themes. The local browser review also includes the landing page at 768px and 1024px. Study-flow tests use simulated Clerk, Supabase, and inference responses. The database harness starts disposable PostgreSQL, and the PostgREST harness exercises HTTP conflicts, retry receipts, authorization, and concurrent Study Chat accounting. Production OAuth, live inference billing, production traffic, and individual catalog explanations were outside the live review. Generated reference validators check their own documented examples.
